# Rona AI Edit

AI Edit is part of `/retouch`. LaMa erases brushed objects; SD 1.5 Inpainting fills a brushed area with an English text prompt. Both run locally. Opening the tool does not load a model. Preview is temporary; Apply reprocesses and commits one snapshot in the editor's existing Undo/Redo history. Cancel clears mask/preview and requests cancellation of an active job. Existing applied layers and original pixels remain intact.

## Installation

The development environment has the models and dependencies installed. For a clean environment, use its Python to install `requirements-ai-edit.txt`, then run `tools/setup_ai_edit.py`. This is an explicit installation step requiring internet; editing itself uses `local_files_only=True` and never downloads models. Weights are under `models/ai-edit`; SHA256 provenance is recorded alongside them. LaMa uses IOPaint's published TorchScript export (MD5 checked against upstream); SD uses the safetensors FP16 components of `stable-diffusion-v1-5/stable-diffusion-inpainting` at a recorded revision. Include the full folder and dependencies in a future portable rebuild. The existing portable executable has not been rebuilt in this step.

## Resource behaviour

One model and one image job at a time across HTTP Upscale, Retouch and AI Edit. Starting AI Edit unloads the Retouch manager; starting Retouch/Upscale unloads AI Edit. The old Upscale model/pipeline files are untouched. AI Edit releases its models after every job, including failure/cancellation. The shared HTTP dispatcher reserves a job under a lock, so competing requests receive 409 rather than starting simultaneously.

Brush strokes and erase stamps are normalized coordinates, capped at 20,000 painting points plus a separate 20,000 eraser-point reserve. Backend validation rejects invalid/non-finite values and empty masks. Transparent source pixels are excluded. The mask bounding box plus context (default 64 original pixels) is processed at a chosen longest edge of 512, 768 or 1024 pixels (default 512), retaining aspect ratio and padding to multiples of eight. Only masked pixels are blended back; feathering occurs inside the mask, so unmarked RGBA pixels and the entire alpha channel remain byte-exact. Very large masks lose fine detail at this work resolution; choose smaller areas for detailed edits.

LaMa uses FP32 (Fourier operations) with the bounded work area. SD uses FP16 on CUDA, VAE tiling, attention slicing, batch one, and sequential CPU offload by default. Turning off the low-memory setting switches to model CPU offload; it does not mean loading all models onto the GPU. CPU inference uses FP32. SD defaults: 20 steps, strength .95, seed 0. Safety checker remains enabled. No ControlNet, segmentation model or translator is loaded. Prompt understanding is primarily English.

The progress bar is indeterminate while loading/setting up and follows actual SD denoising callbacks afterward. LaMa cannot expose internal fractional inference progress; it reports stage boundaries. Cancel stops at the next processing checkpoint, not during a single LaMa forward pass or blocking model load. The UI stays locked until the worker stops and stale results are discarded. Mask editing offers icon buttons for Brush, Penghapus, Geser, visibility and clear, with tooltips and accessible labels; holding Space pans instead of painting. Before shows untouched original and restores an uncommitted AI Edit preview when released.

Temporary sessions are separate from Retouch/Upscale history: at most four documents, 20 committed results and 256 MB per document. Preview replacement removes older previews. Release/page close requests remove session files; normal server close cancels active work and cleans its temporary directory after it stops. Export is needed to retain a result after closing the editor. Reopening a new photo releases the old session.

## Validation

`python -m unittest discover -s tests -p 'test_*.py'` covers mask validation, compositing invariants, session/result/revision checks and existing protected modules. Node tests in `tests/ai-edit-controller.test.mjs` exercise prompt gating, preview/apply separation and cancellation races using a fake DOM, not browser interaction.

`tools/smoke_ai_edit.py` exercises the real local HTTP API and both GPU models using one generated 192x192 fixture with a work area scaled to 512 px. Results are recorded in `audit/ai-edit-gpu-smoke.json`. On the RTX 3050 Laptop 4 GB test: LaMa 2.42 s, peak PyTorch allocation 392.7 MB/reservation 584 MB; SD 1.5 22.55 s, allocation 747.5 MB/reservation 796 MB (10 requested steps, strength .95, low-memory mode, including loading). These are one smoke test, not general timing or total GPU usage guarantees. Unmarked pixels and alpha were exact for both results. Real photo quality and web interaction testing remain with the user.

The entire Retouch workspace accepts up to 50 MP / 256 MB per source file; the shared backend image upload limit is also 256 MB because browser-rendered PNG can be much larger than the original JPEG. Export is capped at 50 MP. The AI Edit work area defaults to 512 px and can be selected as 768 or 1024 px, and session result storage remains 256 MB per document. Large-photo memory/performance and web interaction testing are left to the user.

Mask request JSON is limited to 8 MB for AI Edit only. Ordinary Retouch request limits remain unchanged. Rendering appends only new stamps instead of replaying the full mask after each pointer move; duplicate nearby stamps are skipped. Clear, Cancel, Apply and document changes reset both budgets and the limit notification. Eraser stamps are replayed in sequence by both frontend and backend, so later paint can cover an erased area again.

Processing resolution is in AI Edit advanced settings and is remembered independently per model for the current page session. SD 1.5 labels 1024 px as experimental. Changing resolution discards only an uncommitted preview, preserving the mask and applied edits. The chosen resolution is included in Preview/Apply requests and the committed history settings. A GPU memory error at 768/1024 exposes a button to retry the same operation at the next lower size; no automatic rerun occurs. Both models share the new sizing/compositing tests with stub inference; real GPU capacity, result quality at higher sizes and web interaction tests remain with the user. The previously measured GPU smoke timings remain specific to 512 px.
